## Fix: Split Whisper output into sub-segments using internal timestamps

### Problem
Diarization groups multiple speech segments into one text block because:
1. VAD redemption (2000ms) bridges pauses into long segments
2. Whisper collapses all internal sub-segments into one string
3. Each VAD segment = one DB row = one UI block

### Solution
Add `transcribe_audio_with_segments()` to WhisperEngine that preserves whisper's internal sub-segment timestamps. Apply in import, retranscription, and live recording.

### Files to modify

1. **`frontend/src-tauri/src/whisper_engine/whisper_engine.rs`**
   - Add `WhisperSegment` struct: `{text: String, start_cs: i64, end_cs: i64}`
   - Add `transcribe_audio_with_segments()` method:
     - Enables timestamps (`set_no_timestamps(false)`)
     - Returns `Vec<WhisperSegment>` with per-sub-segment text and timestamps
     - Fallback: if 0 segments, return single segment with full text

2. **`frontend/src-tauri/src/audio/import.rs`** (lines ~595-630)
   - Replace `transcribe_audio_with_confidence()` call with `transcribe_audio_with_segments()`
   - Map each `WhisperSegment` to `(text, start_ms, end_ms)` using VAD segment start + whisper offset
   - Add to `all_transcripts` vec — each becomes separate DB row

3. **`frontend/src-tauri/src/audio/retranscription.rs`** (lines ~375-400)
   - Same change as import.rs

4. **`frontend/src-tauri/src/audio/transcription/worker.rs`** (lines ~475-520)
   - Replace `transcribe_audio_with_confidence()` with `transcribe_audio_with_segments()`
   - Emit one `TranscriptUpdate` per sub-segment (with correct timestamps)
   - Each sub-segment gets its own `sequence_id` and `embedding::push_window()`

### No changes needed
- DB schema (already supports multiple rows per meeting)
- Frontend (already renders 1:1)
- `create_transcript_segments()` in common.rs (already maps 1:1)
